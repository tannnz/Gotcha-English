# 分发流程

## 分发入口

- **独立 Skill：** 提供 `skills/<name>/` 的完整目录地址。支持的安装器可从 GitHub 仓库按名称选择；引用资源必须一起安装。
- **本地市场：** Codex 和 Claude 市场目录读取仓库根目录 `./`。本地验证无需 ZIP，不需要官方市场发布。
- **Git 市场：** 用户或工作区配置仓库来源后，客户端按市场目录读取插件。需要有效访问权限；上传到 GitHub 不表示官方已收录。
- **官方市场：** 按提交时的官方要求准备、上传、验证和发布。公开目录是否收录与结构是否有效分开判断。

当前仓库公开，可作为独立 Skill 和 Git 市场的分发来源。公开可读取不代表市场已经抓取或收录；官方市场仍需要单独提交。后续加入第三方资源时核对授权，许可证单独维护。

## 版本与生成文件

版本统一维护在根 `plugin.json`，文档不重复维护版本值。发布教学内容、插件元数据或分发结构更新时提升版本，再同步平台说明文件。市场标识 `gotcha-english-local` 和插件标识 `gotcha-english` 保持稳定。

```sh
python3 scripts/package-plugin.py --sync-metadata
python3 scripts/package-plugin.py --check
python3 -m unittest discover -s tests
git diff --check
```

审查生成文件差异和所有待分发文件。不要手动修改兼容说明文件，也不要从客户端缓存回写内容。

## ZIP 导出

```sh
python3 scripts/package-plugin.py
```

无参数运行先检查，再生成 `dist/` 中的 ZIP，不隐式改写仓库源文件。ZIP 使用单一顶层插件目录，仅包含运行所需的插件说明、审核后的 Skills 及支持资源；不包含开发文档、测试材料、市场目录或临时文件。重复生成相同内容应得到一致产物。

检查 ZIP 的文件清单与资源引用，再按目标市场当时的官方提交规则校验。生成成功不表示上传成功，也不表示市场已发布。

## GitHub 与市场更新

推送、上传、改变可见性和发布均按用户明确指示执行。GitHub SSH 使用 `github-codex`，默认分支为 `main`；提交前仅加入审核后的任务文件，不捎带已有无关修改。

交付分别报告 GitHub 推送、市场同步、ZIP 上传与发布结果。Git 市场更新按客户端支持的刷新机制完成；本地安装和缓存更新见[开发流程](development.md)。官方 ZIP 分发更新需按市场流程重新提交，不会因为本地文件变更自动更新。
